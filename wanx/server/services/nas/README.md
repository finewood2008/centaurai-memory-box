# 外接存储盒端服务

硬盘管理入口为「配件 → 拓展存储硬盘」。已授权的「文件与问答」使用登记的 USB 卷 UUID，仅匹配当前服务用户挂载在 `/run/media/<用户>` 或 `/media/<用户>` 下的外接卷。系统重新挂载同一卷后会按 UUID 重新定位。外接 NAS 卡片预留。

在盒端用普通用户运行 `python3 -Es service.py /受保护目录/device.json`，该用户应能访问已挂载的目标卷。配置及其目录仅允许服务所属用户访问。配置字段包括设备显示名 `label`、卷标识 `uuid`、初始挂载点 `mount`、授权子目录 `folder`（空字符串代表盘根）、绑定的 `box` 与 `user`、回环服务 `port`、独立的随机 `token` 和盒内模型 `model`、`modelPort`。照片预览依赖 Pillow，PDF 文字提取依赖 pdftotext。

客户端主进程按当前盒子、账号及资料身份选择安装方交付的专用连接配置，拒绝身份不匹配的调用。79 联调通过经主机密钥校验的 SSH 回环转发连接盒端。业务端口只绑定 127.0.0.1。客户机重新建立转发后应同步客户端的本地端口。渲染页面无法读取连接凭据。

上传与下载单文件最大 200 MB。上传先写临时文件，完成后才以目标名称出现。移入回收站的文件保存在同一卷的隐藏目录，按原路径还原。目标有同名文件时返回冲突。问答项目独立保存在盒端数据目录中，用户可单独确认将问答结果存入记忆。图像问答使用文件属性，图像预览单独按需生成。

在 Linux 服务目录执行 `python3 -Es -m unittest -q test_disk`，可验证同名保护、中断上传、越界路径、符号链接、移动及还原。

个人客户端的「空间」通过独立的只读接口列出当前盒端桌面用户已挂载的 USB 文件系统。部署时在盒端 device.json 和该账号、盒子对应的客户端 connection.json 中写入同一份独立随机凭据 `spaceReadToken`（至少 40 个 URL 安全字符）。原配件凭据仍仅用于其登记的授权目录。空间卷浏览仅支持列目录、文本和图片预览，使用与现有配件相同的回环连接。

「配件 → 拓展存储硬盘 → 硬盘管理智能体」区分已挂载、已检测到但没有可浏览卷、未检测到和服务不可用。客户端以 `{"inventory":true}` 调用 `POST /space/volumes`，用同一只读凭据获取文件系统、容量和挂载状态。旧服务返回的卷列表仍可用于空间浏览。智能体里的显示名称保存在本机，按盒子、账号、资料身份和卷 UUID 保存，留空恢复卷标。

外接硬盘的原文件在线编辑另用独立随机凭据 `spaceEditToken`，在盒端和对应账号客户端的同一对配置文件中配对。读取预览与现有配件凭据均不能提交文本修改。编辑限于此用户在已挂载 USB 卷上的可写普通文本文件（UTF-8，最大 16 MiB）。

同一块外接盘也可以成为个人「空间」中的独立存储位置。新版客户端通过配对后的 NAS 服务识别可写卷，由空间服务在实际挂载点下建立私有对象目录。从空间上传、编辑和回收的文件保存在该卷里，文件索引和用户授权沿用现有空间服务。

NAS 与空间服务需要在各自的运行环境中看到同一挂载路径。盒端采用容器时，部署方需要把对应磁盘挂载路径映射给空间服务，并授予其服务用户对空间对象目录的写入权限。挂载路径应位于 `/run/media`、`/media` 或 `/mnt`，空间服务会检查路径仍是挂载点。外置盘断开后，空间不会将文件写入挂载点下方的系统盘目录。

盘上已有的普通目录可以从「浏览盘上原有文件」打开，选中文件或进入文件夹后可复制到任一空间。复制使用 NAS 配对凭据分块读取，通过空间上传接口校验和保存。
