# 万象内置星图

个人客户端的「星图」面板源码。迁自 `centuarai-wanx-startlink`，以建仓、资料导入与自动抽取、知识图谱、材料检索、本体类型与关系管理为范围。抽取模型配置、任务状态及材料核对作为这些流程的依赖保留。

## 源码与运行

- `ui/`：建仓、资料、图谱、检索界面及工作台容器。
- `frontend/`：React 本体与材料知识编辑工作台，含图谱组件和来源核对。
- `shared/`：星图内部动作合同、参数和发布校验。
- `shell/`：材料上传、检索、本体等服务调用，复用 Bridge 路由。
- `integration/`：个人客户端 Host 适配、受限面板桥和布局。
- `tools/assemble-panel.mjs`：将界面和前端构建装配到客户端 `build/app/local-ui/starlink/`，服务适配打包到 `shell/starlink-panel-service.mjs`。

不依赖原项目的绝对路径，不启动独立 Electron 应用。Host SDK 直接使用 `../personal-client/host-sdk/`；未复制独立应用的 SDK 或用户状态。账号、盒子与权限由万象提供，业务请求仍通过 Bridge 到独立 Semantica。

原个人版数据服务仍支持 AI 检索等现有消费方，团队版的简化面板与独立应用快照保持原构建入口。个人版星图面板使用本目录，后续修改请勿编辑旧面板或 `build/` 产物。

## 构建与检查

仓库根执行：

```sh
npm ci --prefix apps/starlink/frontend
npm run test:starlink
npm run build:starlink
```

正常个人客户端构建会自动执行星图前端构建与面板装配：

```sh
npm --prefix apps/personal-client run build:studio
```

依赖既有万象 Bridge 的初始化、会话、材料、本体与工作台接口。`local-data-gate=required` 等模式继续使用服务端现有权限限制，不因内嵌而自动开放尚未支持的流程。

迁移范围、验证和限制见 [接入说明](../../docs/applications/starlink-panel-migration.md)。

## 新建星图

新建时填写名称即可创建。通用知识是默认本体，「更换」可选择项目与协作、资料与研究或业务与流程。客户端在新星图启用所选规则后直接打开资料库。已有星图继续使用各自的本体，可在「本体 → 本体修改」维护。

星图默认使用万象底座提供的模型，可以直接导入资料。需要指定其他模型时，在「模型设置」为当前账号和盒子保存一次，新旧星图的新任务共用此设置。

资料库通过阅读台导入和核对资料，抽取、核对结果与发布均有页面入口。历史资料对话供查阅，星小图是当前星图的对话入口。

## 星小图

星小图优先介绍当前页面，切换页面时更新说明和示例问题，同时保留其他页面的导航入口。对话与未发送内容按账号、盒子、用户和项目隔离。

功能指引使用一句简短说明和一个相关入口，不自动展开本体或检索详情。已在目标页面时，入口显示“定位到…”并聚焦内容；跨页面则显示“前往…”。成功定位或导航后收起浮窗，保留对话与草稿。

普通提问通过独立的 LLM 意图识别请求处理。记忆盒子个人星图的问答和意图识别共用「模型设置」中的星小图模型，默认随平台当前文本模型变化。手动选择按当前账号与盒子在本机保存。返回只允许 `guide / navigate / query / search / ontology_change / clarify / unsupported`，目标与参数必须匹配固定组合。模型不返回 URL、接口、身份或发布确认参数。本体修改由本体工作台处理。

意图协议 v2 发送当前提问、页面、当前阅读资料标题，以及最多四条同项目已完成动作的用户问题、原页面和有限动作结果，不发送正文、完整本体或资料 ID。来源与动作分别判断：明确的资料限定或应用操作优先；“本页/这里”使用当前页面，“它/刚才那个”结合资料标题和已完成动作补足指代，明确对象不会被当前页面覆盖。未知产品的功能问题应检索资料，`guide/general` 只介绍星小图自身能力。

只有合法的 `clarify` 返回才显示意图选择。歧义和多项需求给出两个不同的只读动作候选（指引、导航、项目查询、检索）；缺少可靠对象时给出空候选并要求补名称。候选不能嵌套或包含修改操作，按钮文案由能力目录生成；用户选择后直接执行并记录该动作，不再次分类。明确限定当前资料的检索由客户端绑定资料 ID，候选产生后若切换了资料，需重新提问确认来源。

依赖缺失、接口缺失、连接失败、模型不可用、超时和返回格式错误分别提示原因并提供恢复入口，不默认检索。请求期间切换页面、项目、阅读资料或账号，旧分类不会继续触发操作。统计指标读取真实项目数据，本体修改类请求只显示步骤和本体模块入口。记忆盒子个人客户端通过现有平台文本模型接口调用推理，并校验 v2 意图回执。通过 Semantica 分类的部署仍需同步更新客户端、Bridge、共享协议包和 Semantica；协议不兼容时显示请求格式提示。

功能目录唯一来源为 `shared/packages/local-data-gate/centuarai_local_data_gate/starxiaotu_catalog.json`（仓库根目录下）。修改后运行 `node --input-type=module -e "import {syncStarxiaotuCatalog} from './apps/starlink/tools/sync-starxiaotu-catalog.mjs'; await syncStarxiaotuCatalog();"` 更新客户端生成模块；装配及测试会检查两者一致。由 Semantica 执行分类时，需要同步更新客户端、Bridge、local-data-gate 包及 Semantica 的 `/api/integration/modeling/warehouses/{workspace}/assistant-intent` 接口；旧服务端缺少接口时保留手动功能入口。

本地 Semantica 若安装的是共享协议包的旧 wheel，仅更新仓库源码不会更新其虚拟环境。需重新安装本目录生成的协议包，并在不覆盖共享包搜索路径的环境中验证 `from centuarai_local_data_gate.starxiaotu_intent import CATALOG`，避免测试的 `PYTHONPATH` 掩盖缺失依赖。

星小图以内容区左下角的半透明浮窗打开，桌面最大宽度约 420 像素。页面导航和浮窗外的控件继续可用。点击框外收起浮窗，再打开可继续原来的对话和未发送内容。实体类型、关系方向、属性、来源证据等术语旁的星标会打开对应的解释，并使用当前项目回答。

本体修改在左侧「本体 → 本体修改」完成。用户可手动编辑实体类型、关系类型和属性，保存草稿，核对差异，再确认发布。星小图可以解释当前规则、说明操作步骤并打开该模块。历史资料的重新处理仍需另行确认。

| 用户表达 | 处理方式 |
| --- | --- |
| “这个页面怎么用？”“如何查看本体？”“如何修改本体？” | 一句功能说明和一个导航或定位入口，不读取具体本体。 |
| “如何设置模型？”“如何查看我有多少资料？” | 分别提供模型设置和概览入口，不执行资料检索。 |
| “带我去资料库”“打开本体页面” | 导航到指定页面，遵守原有未保存内容保护。 |
| “当前星图里面有什么”“当前项目有哪些资料？”“我有多少资料？” | 读取项目统计和资料清单，列出可打开的资料来源。 |
| “查看我有哪些本体”“合同有哪些属性？” | 读取本项目真实本体，区分生效版本、草稿和历史版本，并展示类型、属性与关系。 |
| “材料里有没有提到本体设计方法？” | 检索项目资料，提供记录或原文出处。 |
| “给合同类型增加到期日期属性” | 说明添加属性的操作步骤，并链接到「本体修改」。 |
| “帮我看看合同” | 参考当前项目回答，并在有合理的配置方向时提供可选入口。 |
