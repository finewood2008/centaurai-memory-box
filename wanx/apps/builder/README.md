# 万象·开物 · WanX Builder 1.0.1

企业版管理员使用的独立万象应用（应用 ID 仍为 `ai.wanx.studio`）。通过万象应用管理器安装、启动和复用独立进程，不再默认嵌入客户端进程；客户端导航“开物”保留项目和配置快捷入口。应用沿用 WANX Host 的账号、盒子连接与管理员校验，切换上下文后原会话失效。后端仍挂载在同一 WANX 服务，既有项目和数据路径不迁移。

客户端只负责输入需求、AI 补全与确认、资源和 ACP 配置；完整 PRD 问答、受控开发、试用、改进和版本采用在本工作台完成。

## 开发与验证

macOS 可在资源包生成后运行 `npm run package:macos`，产出带有 `ai.wanx.studio` 独立系统身份的“万象·开物.app”及 WANX 应用清单。它仍由万象应用管理器携带当前账号、盒子与 Host 会话启动；不单独保存登录凭据，也不附带另一套后端。macOS 包和通用共享运行时包使用相同应用 ID、版本与数据目录。

```sh
npm ci
npm run dev
npm run check
```

`npm run dev` 是本机隔离界面环境。连接真实 WANX 时，由同一服务进程挂载 `backend/wanx_studio`，沿用当前账号、模型与空间；不会把背景仓库授权自动转成成品应用权限。

`npm run build` 与 `npm run package` 构建开物界面并打包工作台。`tools/assemble-client.mjs team` 将生成资源装配到团队客户端，所有输出均已忽略。源码、锁文件、测试与必要静态资源可提交；构建产物、资料、凭据与业务数据不提交。

产品与部署说明见 [WANX 1.0](../../docs/release/wanx-1.0-release.md)。

## 部署工作区

开物与个人工坊共用 `ui/deployment/`，从已有项目的“部署”页或“部署已采用版本”进入。页面通过现有 `ui/api.ts` 和受信 Host 通道读取真实部署能力、当前应用的近期操作、执行事件、组件结果与回执投递状态；关闭页面不会取消后台任务。

普通应用从已采用版本取得标准 ZIP，在目标客户端校验包摘要并安装。需要盒端专家的项目采用同一份 ZIP，另外绑定专家模板、环境与交付回执。布局预览在隔离环境运行，真实专家调用需要目标客户端和已部署实例。

公共合同、构建来源和当前验收范围分别见[开物公共合同](../../docs/applications/kaiwu-public-contracts.md)、[开发套件装配](../../docs/release/kaiwu-builder-runtime.md)和[单轨改造计划](../../docs/plans/kaiwu-app-kit-standard-only.md)。

## 首次共同设计与后续迭代

首次构建通常按“场景与目标 → 流程与功能 → 页面与验收”共同沟通几轮，每轮通过已有 `ask_product` 工具提出 2–3 个问题。每题标出推荐及取舍，但不预选、不自动发送；用户也可逐题自由补充，或明确指出尚未决定的事项。确认本轮回答后，产品经理增量保存 PRD，右侧高亮实际变化的章节。选择草稿按项目保存在工作台会话中。

首版方案完整且当前问题已回答后，展开包含目标、流程图、功能范围、页面草图、数据、规则和验收用例的完整 HTML PRD；用户确认当前整稿后才开发。方案或连接发生变化时重新校验，旧稿的确认不能启动新方案。文档可下载、离线阅读和打印，接口与连接配置位于底部折叠章节。

首次流程的丰富沟通不影响首版后的直接迭代：已有成功版本继续接受文字／圈选修改，不重走整份 PRD 确认。构建、试用、采用、安装更新与公司上架分别处理。

## WANX 底座硬约束

`backend/wanx_studio/wanx-foundation.json` 是客户端 AI 补全、首次 PRD、后续迭代和代码生成共用的固定约束，由 JavaScript 和已安装的 Python 包共同读取，并随本轮构建方案冻结：

- 只使用 WANX 当前已开放的接口与能力；允许配置已有模型、空间、星图授权和应用访问范围，不修改底层接口，不另起后端。
- 多账号沿用 WANX 登录和管理员／普通用户两个级别，身份及权限由可信会话和服务端决定。应用不能自建登录、注册、密码表或令牌，也不能用自填角色或页面过滤模拟授权。
- 产品经理依据 `availableContracts`、当前能力检查报告和资源授权判断需求。现有接口不可实现的要求保留为缺口，继续讨论现有能力内的可行范围；用户决定前不承诺实现，也不建议通过修改底座解决。
- 首次构建和迭代继续执行接口白名单、资源授权、源码路径、依赖与运行沙箱校验；密码及认证令牌存储在数据契约和编译阶段直接拒绝。

标准应用按 Kit 中的公共合同 ID 声明需求。专家应用使用 `wanx.expert-app.v1` 的固定状态结构。历史 miniapp 的通用数据集合和私有报告接口不进入新建项目与构建方案。
