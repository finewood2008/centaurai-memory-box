# 团队版本地身份移除与星图接入验收

## 验收标准

- 新旧 Windows/macOS 用户目录都只走云账号与盒端原有授权；不加载本地身份、口令或旧开关，不提供解锁、审批和设置入口。
- 团队版底层连接和数据服务不再提供本地身份协议分支；云端撤权、账号切换及盒子切换仍使旧连接失效。
- 正式与内部安装包均排除本地身份模块，构建后检查实际 ASAR；保留云账号签名、凭据加密及用户已有文件。
- 星图安装和 OTA 使用实际 WANX 客户端验证个人、团队、组织只读请求；旧服务协议不能通过新验收。组合升级在全部候选启动后检查，避免旧的对端阻断升级本身。

## 工作与依赖

1. 已完成现场只读诊断：99/105 配置及凭据匹配，个人请求 200、团队请求 401，运行的旧星图镜像缺少团队协议。
2. 客户端启动、登录、连接及 UI 移除：`../../apps/team-client/shell`、`platform.mjs`、`client.mjs`、preload/renderer。服务和数据源同步修改 `../../apps/builder/integration/team-client`。
3. 安装包隔离与云账号上下文：独立迁移通用 helper，再对三条打包路径检查文件闭包及实际 ASAR。
4. OS 构建、安装及 OTA 验收：`centuarai-os/deployment` 与对应测试；使用已提交的 Semantica 团队协议修复，保持服务鉴权。
5. 集成生成物、独立审查、验证后提交并推送；分支推送不等同已部署客户端或盒端镜像。

## 验证

- 针对旧 enabled/locked profile、删除的 IPC/API、云权限撤销、真实打包文件集和 ASAR 的回归。
- Studio 构建和测试、团队客户端完整 Node 测试。
- OS 构建门禁、工厂及 OTA（含组合更新顺序和失败回退）测试；签名正确的旧协议必须失败，匿名/错误签名仍拒绝。
- 仓库要求的 `make all`，记录与本次变更无关的基线问题，不将未通过的验证称为通过。
- 若部署镜像，先确认无活动 OTA，再使用正式部署和收据流程，最后重新运行 99/105 的只读请求；不通过修改受信基线掩盖漂移。
