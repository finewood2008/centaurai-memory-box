# 专家后端与配套客户端实施计划

目标：开物按标准交付一个冻结目录，部署模块在当前指定盒子准备私有专家并交付配套客户端，完成真实运行、结果持久化及重启恢复验收。代码来源与开物编辑过程不作为部署前置条件。首版专家入口为文本问答，复用盒端现有专家模板、默认模型和 gateway，运行于 SSO 可信上下文。

## 接口与职责

- 目录入口只接收 `releaseId`，从受信 inbox 的 owner 隔离目录读取，不接受浏览器提供文件路径或启动命令。入库校验完整目录并保存不可变副本，以目录摘要关联原三项合同。
- 新运行 profile 为 `wanx-expert-app-v1`。专家模板内容版本使用固定摘要生成的版本号，不伪造上游不存在的模板 SemVer。私有实例按 owner、box、应用、环境和后端描述隔离；实际实例 ID 不下发应用。
- 客户端复用已有 `foundation.invoke` 通道，仅开放 `expert.run`、`expert.tasks`、`expert.cancel`。参数只含幂等标识、文本或运行 ID；运行历史来自盒端，断网不自动重发业务输入。
- 部署继续复用既有客户端票据、managed 槽位和 Coordinator。目录发布与工坊项目分开，不重新编译或改写交付应用身份。个人工坊作为当前受信 Host 传输入口，交付来源仍为独立的标准目录。
- 专家运行由盒端 gateway 接纳；客户端关闭后继续。服务重启后未证明完成的运行标记中断，不自动重放。发布前候选仅执行受限文本健康探测，不开启工具、外部写入或调度。

## 验收标准

标准目录可以被确定性验证与冻结；同发布 ID 不同内容拒绝。两个环境有独立私有实例和数据，未绑定或跨用户／应用／旧代次请求拒绝。客户端实际安装后才确认交付，盒端专家真实响应后才证明执行入口可用；关闭页面不取消已接纳任务。重复请求不重复 enqueue，未知结果不伪报成功，服务重启不自动重放。既有 miniapp 数据／资源部署与连接恢复回归保持通过。

依赖既有模板目录与 AgentManager、ChatTurn 准备／gateway／线程历史、StudioStore SQLite、Coordinator、客户端受信 runtime 和标准目录合同。新入口先保持 SSO；本地信任模式继续遵守原有任务授权与文本限制，不通过内部调用绕过。
