# 开物作为部署最终验收入口

目标：从原开物 `ai.wanx.studio`、`/api/app-studio` 和 StudioService 出发，接收符合三项交付合同的标准目录，在指定盒子完成 dev／prod 部署、客户端自动安装、专家调用及持久化验收。按用户明确的团队边界，部署不限定上游代码如何生成；用独立合成目录验收时须明确标注来源，并使用新应用身份，不能伪造项目／任务／采用记录或接管工坊槽位。原开物正常生成、采用及项目导出作为补充集成验收单独记录，不能被目录部署成功冒充。

## 已确认事实

昨天实机仅覆盖 PersonalWorkshop 和个人客户端的目录部署。原开物未初始化部署适配器、不能分发部署专家调用；企业客户端缺少 managed 安装与 delivery worker。客户端 namespace 固定为 workshop。开物 artifact 的谱系 hash 与目录客户端 payload hash 不同。foundation 原合同是来源应用原生能力，不能直接冒充新部署专家合同。

## 接口及影响范围

- 保留原开物管理员／SSO 身份，业务代码位于 WANX；不修改 Octop 核心、App Kit 或云端账号规则。Local Trust 仍明确拒绝本 profile，不能取消原 guard。
- 共用既有专家／协调执行模块，各自保留 Studio、Workshop Store。新增 server-root 持久槽位归属注册表：启动先读取双方历史 binding／preparation 后一致 seed；同源幂等，跨来源同 owner＋完整 target 永久冲突，不改 organizationId，不允许两个 Coordinator 接管同槽位。运行、安装和激活持续复核来源。
- namespace 只能由受信装配配置。Intake 严格验证对应 studio／workshop；Studio 客户端运行经 `/api/app-studio`，旧工坊应用保持原路由。managed audience 只允许自己的 slot／session，不得管理项目和部署。
- 开物显式选择版本化文本专家合同，预检真实模板／默认模型依赖，生成合同和采用快照保留该引用；候选部署仍执行真实专家验证。普通 foundation／知客语义不变，不伪造 capability report。
- 交付出口只读取已完成并已采用 artifact，校验 adoption revision、源 hash、内容完整性、冻结合同及当前权限。确定性包装原 bundle／css／manifest，不重新编译、不改源 artifact hash；另算目录 payload hash，并保存可追溯来源。
- 企业客户端复用有限票据协议，补 managed 安装全部防接管保护；worker 仅 main process 持有，不增加 renderer 任意 binding 安装入口。不复制个人版账号、vault 或安装身份。
