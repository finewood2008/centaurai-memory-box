## 四、管理员执行清单

以下按依赖顺序执行。构建可提前完成；数据库迁移必须在新服务的 schema 预检及启动之前完成。

命令示例使用 Linux Bash。执行前由管理员设置实际路径和地址，不把下列占位值直接用于部署：

```bash
export ADMIN_REPO='/实际候选源码目录/nexusaos-admin'
export BACKEND_PYTHON="$ADMIN_REPO/admin-backend/.venv/bin/python"
export STAGE_ORIGIN='https://实际预发域名'
export STAGE_EVIDENCE='/实际预发验收证据目录'
umask 077
mkdir -p "$STAGE_EVIDENCE"
```

发布器示例中的 `RELEASE_TOOL`、`STAGE_RELEASE_ROOT`、`STAGE_SPEC`、`STAGE_RELEASE_ID`，由各服务管理员根据现有预发流程分别填写；Admin 和 Consumer 不共用一个发布状态目录。

- [ ] 构建 admin 和 consumer 镜像，记录不可变 digest、制品清单及流水线运行号。消费端制品必须打入共享 FAQ controller/Service/DAO。

### B. 备份并执行数据库迁移（DBA）

- [ ] 按现有备份流程保存目标数据库及菜单、当前镜像／静态版本和 nginx 配置。
- [ ] 用受保护的预发迁移连接核对实例，不使用应用运行账号临时提权执行 DDL。
- [ ] 先执行 FAQ 表结构，再执行菜单脚本。以下假设 DBA 已配置专用 `mysql --login-path`；名称按实际填写：

```bash
mysql --login-path=stage-faq-migration --default-character-set=utf8mb4 \
  -e 'SELECT @@hostname, @@port, VERSION();'

mysql --login-path=stage-faq-migration --default-character-set=utf8mb4 \
  < "$ADMIN_REPO/admin-backend/sql/20261105_faq.sql"

mysql --login-path=stage-faq-migration --default-character-set=utf8mb4 \
  < "$ADMIN_REPO/admin-backend/sql/20261105_faq_menu.sql"
```

- [ ] 检查 `nexus_faq_category`、`nexus_faq_item`、`nexus_faq_content_lock` 均已建立，答案为 MEDIUMTEXT，外键为 ON DELETE RESTRICT，内容锁存在 `id=1`：

```sql
SHOW CREATE TABLE nexus_aos.nexus_faq_category;
SHOW CREATE TABLE nexus_aos.nexus_faq_item;
SELECT id, note FROM nexus_aos.nexus_faq_content_lock;
SELECT menu_id, parent_id, menu_type, component, perms
FROM nexus_aos_boss.sys_menu
WHERE perms IN ('nexus:faq:list','nexus:faq:add','nexus:faq:edit','nexus:faq:delete')
ORDER BY menu_id;
```

表结构脚本会初始化内容锁；菜单查询预期恰好 4 行，页面权限为 C，新增／编辑／删除为 F。

- [ ] 确认目标 MySQL 支持脚本中的 `utf8mb4_0900_ai_ci`，并在预发实测分类名称去重。
- [ ] 以实际 admin、consumer 运行账号检查必要表访问，避免“迁移账号可读、运行账号无权”。沿用既有权限模型。
- [ ] 菜单脚本若因父目录不唯一或已有菜单冲突退出，先核实“业务管理”目录及已有记录；不要跳过校验强行重复插入。

### F. 公网 API 与真实 Redis 验收（consumer 管理员）

把 `STAGE_ORIGIN` 填为预发域名，`STAGE_EVIDENCE` 填为本次预发证据目录。以下请求不携带业务账号凭据，HTTPS 证书必须正常验证。

```bash
FAQ="$STAGE_ORIGIN/prod-api/app-api/faq"
curl --silent --show-error --dump-header "$STAGE_EVIDENCE/faq-200.headers" \
  --output "$STAGE_EVIDENCE/faq-200.json" --write-out 'HTTP %{http_code}\n' "$FAQ"
```

- [ ] 预期真实 HTTP 200，信封 `code=200`、`success=true`；data 包含 version、updatedAt、categories/items，且只含上架分类中的上架问题。
- [ ] 响应带 `Cache-Control: no-cache` 和 `ETag: W/"faq-…"`。
- [ ] 从实际响应头**原样复制 ETag**（包括 `W/` 和引号），进行条件请求：

```bash
# ETAG 必须替换为上一响应的实际值。
ETAG='W/"faq-实际响应中的版本"'
curl --silent --show-error --header "If-None-Match: $ETAG" \
  --dump-header "$STAGE_EVIDENCE/faq-304.headers" \
  --output "$STAGE_EVIDENCE/faq-304.body" --write-out 'HTTP %{http_code}\n' "$FAQ"
```

- [ ] 预期 HTTP 304、空 body、同一 ETag；不能把 HTTP 200 + `code:304` 算作通过。
- [ ] 后台改一条公开答案，再携带旧 ETag 请求：应为 200、新答案、新 ETag。
- [ ] 下架测试分类，保留其条目上架状态：这些条目不得公开。若环境中已无任何公开分类，`categories=[]` 且 `updatedAt=null`。
- [ ] 只编辑隐藏分类下的条目：公开 ETag 不变，原条件请求仍为 304。测试结束后恢复正常测试内容。
- [ ] 使用 `Authorization: Bearer deliberately-invalid-test-token` 请求同一 URL，应仍为 200，与匿名 data 和 ETag 相同；没有真实 token 参与测试。
- [ ] 响应体超过 1000 字节且请求带 `Accept-Encoding: gzip` 时，检查压缩和 `Vary: Accept-Encoding`，不得包含 `Vary: Authorization`。
- [ ] 用指定预发测试来源，在同一分钟窗口验证真实 Redis 计数达到阈值后返回 HTTP 429、`Retry-After` 和 `Cache-Control: no-store`，等待窗口恢复。若请求跨分钟，重新核对计数，不能据一次跨窗口的 61 次请求直接判错。
- [ ] 503 故障验证仅在专用测试副本或隔离实例执行；共享预发数据库不做缺表／停库操作。不具备隔离条件时记录为尚未执行，保留已有本地 MySQL 故障证据。
- [ ] 对 `/consumer-api/app-api/faq` 重复正常读取和 200→304 检查。记录客户端本轮实际使用的前缀。

管理员先通过后台创建并上架一条专用测试问答，再由我验证客户端。

| 场景 | 管理员操作 | 万象侧检查 | 通过标准 |
|---|---|---|---|
| 首次读取 | 上架分类和问题 | 两端进入 FAQ | 显示后台相同内容，无需登录或连接盒子 |

| 内容不变 | 不改数据 | 再次刷新 | 实际 If-None-Match → 304，页面保留内容 |
| 隐藏内容 | 下架分类后编辑其条目 | 刷新 | 无隐藏内容，ETag 不因隐藏编辑变化 |

| 登录入口 | 保持客户端未登录 | 登录／注册／找回密码页进入 FAQ | 可进入、可返回原界面 |
| 设置入口 | 提供可用测试登录 | 头像 → 设置 → 常见问题 | 正常进入和返回 |
