# 万象工坊 PRD 部署环节对照与方案调整

> 平台部署设计现由万象仓库维护；从应用开发套件迁入。当前代码位置、实际能力与本轮范围以[Builder 部署接入计划](kaiwu-deployment-ui-integration.md)和[后台实施记录](kaiwu-deployment-backend.md)为准。套件公共合同草案及离线工具仍保留；合同源码引用固定到迁移时的套件提交，公开能力指南使用持续更新的分发入口。

需要调整现有方案，但调整限于部署模块的输入、执行适配和交接合同。用户已明确：只负责 PRD 中的部署环节，其他功能由另一位同事开发。修订后的主方案见[万象工坊应用部署技术开发方案](kaiwu-box-deployment-plan.md)。

部署继续负责单盒执行、候选准备、前后端交付、环境隔离、版本激活、数据迁移调用、失败恢复与运维。规格编辑、专家／流程运行时、组织权限、审批、业务回归、企业微信接入及组织应用目录业务均不转移到部署团队。

## 三 保留的部署设计

原方案中可继续采用的部分包括：

- 持久化控制模块与盒端执行模块，任务不依赖页面或当前 Host 会话。
- 不可变制品、摘要与来源校验、候选验证和真实端到端回执。
- dev／prod 隔离、客户端本地数据 staging 副本、同环境操作锁及 fencing token。
- 幂等重试、断线对账、提交前补偿与恢复失败状态。
- 数据快照、密钥引用不落源码和日志、任务租约不复制。
- 停启卸载、明确数据删除、资源预留与配额、日志及历史。

这些设计不依赖由我们实现规格编辑器、组织系统或业务工作流。部署层不开发另一套发布审批、回归评测或企业微信接入。

## 四 与同事必须对齐的 Interface

| 共同合同 | 同事提供 | 部署提供 |
| --- | --- | --- |
| DeploymentBundle | 冻结规格或代码制品、固定依赖、runtime／客户端交付声明。 | 登记、来源摘要校验、预检和制品准备。 |
| Runtime Adapter | 加载应用、候选模式、健康检查、应用级停启、实例版本固定及恢复语义。 | 持久调度、候选与环境切换、故障对账。 |
| 发布与回归结果 | 是否允许发布、范围与资料绑定、回归结果及有效性查询。 | 核验与本版本／目标一致，不自行制定政策；首次 dev 可先部署试运行，正式激活才要求对应回归证据。 |
| 客户端与 Channel Adapter | 安装／加载、路由准备／激活／查询、成员身份和业务权限。 | 收集技术回执、协调版本切换、展示分项失败。 |
| Data Adapter | 新增字段兼容计划、快照恢复、可选初始化数据、任务检查点与对账。 | 环境锁、维护屏障、调用与回执、提交前失败恢复。 |
| 激活结果与审计 | 应用业务状态机、组织目录及审计接收合同；按环境代次处理跨操作乱序。 | ActivationReceipt、至少一次可靠事件投递和查询对账；不直接把业务状态改为已发布，投递失败不重做部署。 |

共享 runtime 的停用／卸载必须针对单个应用，不能停止其他应用共用的进程。任意历史版本回滚还需要 runtime 与依赖的长期可用性；只保存规格元数据不等于可运行。双方先固定这两项约束，避免交付时发现“部署接口成功但组织应用不可用”。

## 五 开发与验收调整

主方案的 D0 至 D4 仅表示部署内部里程碑：合同核实、单盒测试闭环、正式激活与入口联调、保数据历史回滚、运维与故障验收。原完整 Fork 编排不再阻塞首条正式部署链路，也不把 PRD 的组织 P0、两个销售模板、培训或社区排到我们的开发任务中。

部署直接承担正确目标与版本激活、放行结果绑定、版本回滚保数据、故障恢复及可追溯回执。A3、A4、A5 需要联合验收；A6 的资料与 AI 写入规则、A8 的组件兼容性也由同事模块提供保障。A1、A2 的无代码构建和 A7 的超界引导不属于部署实现。部署成功不能代表整个产品 MVP 验收通过。

首个联调只需同事交付一份真实可运行版本，以及上述最小 Adapter 与放行结果；先完成真实盒子的完整部署回执，再扩展运维与历史恢复，不从头承接整个工坊。

## 六 交接可执行性复核

主方案是部署行为与合同字段的设计依据；本文保留 PRD 差异及调整理由，不另行维护一套字段定义。三项外层合同在主方案第三节汇总，重试与回执交付在第十节规定，冻结门槛在第十四节列出。

| 复核发现 | 已补充的约定 | 联调必须验证 |
| --- | --- | --- |
| 包、请求和回执字段散落，目标配置易混入不可变包。 | 明确生产者／消费者、schemaVersion、摘要、字段归属及按 kind 的必填条件。 | 同版本转正式不改包；同 releaseId 异摘要拒绝；不支持的合同版本预检失败。 |
| 重复回执可去重，但旧操作迟到仍可能覆盖新版本。 | 操作历史与环境当前状态分别消费，按 generation 和 environmentRevision 对账。 | 先发布 A 再 B，A 的迟到成功不能把目录改回 A；同版本停用也不被旧成功重新开放。 |
| 成功后健康下降、回调失败和部署失败混为一谈。 | 操作终态、环境健康、回执投递状态分离，安全终态不等投递才释放锁。 | 回调重试不重新部署，后续告警不改写历史成功。 |
| blocked 修正与原幂等键不匹配，等待可能无限占锁。 | 内容不变可续跑；改变引用用新请求关联旧操作；等待超时安全补偿或由内部 recover 操作受控接管。 | 失联和证明补齐后不重复迁移，失败任务不永久锁死环境。 |
| 多入口部分激活与紧急停用缺少收敛路径。 | 有限对账、明确已提交但降级的结果；停用先封入口，物理清理仍串行。 | 某 Channel 永久故障不假成功；部署中撤权不会被长操作锁拖延，失联设备显示待确认。 |
| 排空在途操作可能被实现成等待人工流程结束。 | 仅排空执行中的短步骤，长期实例保存检查点并暂停唤醒。 | 等待人工的流程不阻塞整个发布，也不会被重新创建。 |

这些补充属于部署合同和恢复语义，不新增产品审批、业务工作流或 Channel 实现。双方仍需将草案固化为 Schema、成功／失败样例及 Adapter 契约测试后，才能作为正式联调合同。
