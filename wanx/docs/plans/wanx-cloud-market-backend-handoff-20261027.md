## 已接入的现有接口

| 接口 | 客户端处理 |
| --- | --- |
| `GET /app-api/market/apps` | 目录的唯一来源；按 `applicationId` 关联本机安装记录；空目录不补造应用。 |
| `POST /app-api/market/apps/{applicationId}/candidate` | 使用真实操作系统、架构和本机版本查询兼容候选；显示可安装、可更新、最新、本机较新、不兼容或不可用。 |
| `POST /app-api/market/artifacts/{artifactId}/download` | 用户确认安装时重新核对候选，申请临时 HTTPS 地址；不保存固定下载地址。 |
| `POST /app-api/market/artifacts/{artifactId}/access` | 保留既有受控版本/灰度准入校验，不以目录可见代替使用授权。 |

继续复用 `account.request` 的 Consumer 会话、请求签名和业务错误检查（包括 HTTP 200 中的业务 401）。发行包仍经 Ed25519、平台、版本、字节数、SHA-256、压缩包路径和清单校验；失败不覆盖可用版本，不自动降级。

## 当前字段如何显示

| 当前字段 | 客户端行为 |
| --- | --- |
| `applicationId` | 稳定关联标识，不用本地应用名单限定目录。 |
| `name` | 显示云端名称，移除按 ID 强制改名的例外。无有效名称的目录响应报错，不补造名称。 |
| `description` | 显示云端文字；缺失或为空时省略介绍，不填本地营销文案。 |
| `iconUrl` | 优先使用 HTTPS 云端图标；按产品负责人确认，缺失或加载失败时临时使用原有本地图标。没有对应素材的新应用使用通用字母占位。 |
| `listed` | 不展示明确为 false 的条目。 |
| `createdAt`、`updatedAt` | 保留元数据；不将更新时间当成发行版本。 |
| `release.version`、`release.notes` | 来自本机候选；说明为空时不展示更新说明。 |
| `artifact.os/arch/size` | 来自候选，展示真实平台与包大小；缺少则省略。 |

已安装应用即使从云端下架，仍可在「我的应用」找到真实本机安装记录、按原有运行授权打开、管理或卸载。这不是内置目录兜底。未安装、云端也未返回的应用不生成卡片或介绍页。

## 离线行为

按已确认的产品要求，仅加密保存每个 Consumer 环境、每个账号最后成功取得的目录。两版客户端使用各自用户目录。

- 网络不可用或服务端 5xx 时，可展示该账号的上次目录，明确标注离线及缓存时间。
- 首次无成功缓存时显示加载失败与重试，不显示本地固定推荐。
- 登录过期、权限拒绝、无效响应、取消或账号切换不伪装为离线缓存成功。
- 离线目录不提供缓存安装/更新授权；恢复网络后再获取候选及临时下载地址。
- 不缓存 Consumer token、签名、MCP Key、候选签名信封或临时下载 URL；只保留目录字段。
- 已安装应用沿用既有运行准入规则；受控版本仍要求有效许可，不承诺所有应用可离线运行。

接口文档的 HTTP `Cache-Control: no-store` 保持原样。本次缓存是用户明确要求的客户端账号范围加密目录快照，不改变 HTTP 缓存或下载授权策略；如后台以后需要主动禁用该快照，应补充明确的客户端缓存策略合同。

## 后台联调核对清单

1. 用已登录 Consumer 账号取得目录；修改后台名称、描述、图标后，客户端刷新即变化。
2. 新上架一个从未写进客户端源码的 applicationId，两版客户端均可发现；下架后不再发现，本机已安装版本仍按原规则管理。
3. 四种目标（macOS/Windows × arm64/x64）候选正确；通用包和精确目标选择、灰度名单、同版本制品冲突、本机较新版本均遵守现有合同。
4. 点击安装时重新核对候选；临时 URL 过期重新申请；错误签名、错误字节数/哈希拒绝安装。
5. 目录字段为空时不补充本地文字、分类或默认安装行为；产品负责人批准的临时本地图标和海报除外，且只匹配真实目录／安装记录。
6. 网络故障可见账号自己的离线目录；401/403 不绕过，切换账号不串目录。
7. 默认安装策略尚未定义前，后台与客户端验收均应预期「不自动安装」。
