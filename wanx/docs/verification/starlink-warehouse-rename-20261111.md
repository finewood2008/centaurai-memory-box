# 星图数据仓重命名验收

## 范围与验收条件

- 个人版和团队版共用星图界面，在“选择数据仓”每行提供重命名，并在“更多”中提供当前数据仓入口。
- 改名只更新显示名称与更新时间，保留数据仓 ID、选择状态、说明、资料、本体和图谱；抽取任务运行时允许改名。
- 名称去除首尾空格后为 1–60 个 Unicode 字符，不含控制字符；同一所有者不能重名。
- 个人数据仓保持个人写权限，团队数据仓要求执行权限，不开放只读成员写入。
- 网络响应丢失后复用原数据仓、名称和操作 ID；已收到成功回执但后续读取失败时，只重新读取。

## 实现与发布依赖

客户端界面位于 `apps/builder/integration/team-client/data-view.js`，由官方 assembler 生成两版客户端资源。请求经过有限 IPC、个人/团队数据服务、Bridge 与 shared local-data-gate，进入 Semantica 的 `PATCH /api/integration/warehouses/{id}`。接口只接收名称和稳定操作 ID，服务端保存幂等回执。

需要配套发布 Semantica、包含新版 shared 包的 Bridge，以及重新构建的个人/团队客户端。旧 Semantica 不支持该接口时提示升级。无数据库结构迁移，无新增功能开关。

## 验证结果

- 客户端界面、个人/团队接线及实际 preload：124 项通过。
- shared、Bridge desktop 与 transport：270 项及 32 个子测试通过。
- Semantica 新增改名及 local-data 权限用例：12 项及 14 个子测试通过；后端代理另完成既有数据仓相关回归。
- 个人版、团队版官方 assembler 构建通过；生成资源包含改名操作。
- 使用独立浏览器配置和合成数据检查选择窗口、改名保存及无横向溢出；未修改真实数据仓。

尚未部署到盒子或发布客户端安装包。
