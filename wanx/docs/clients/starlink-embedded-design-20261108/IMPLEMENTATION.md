## 界面

个人版与团队版复用 `apps/builder/integration/team-client/data-view.js` 和 `data.css`。数据仓成为独立选择条，导入是主操作，主要视图仅保留“知识图谱”和“资料”。检索、实际整理任务、来源和待确认事项按需进入侧栏；紧凑窗口使用可关闭的详情抽屉。

“打开完整版”只保留在页首右侧原有“更多”菜单中，默认隐藏，菜单内保留刷新。主界面、资料卡、授权摘要不再增加显眼的完整版入口。高级能力在完整版处理，简化版不展示本体配置。团队版在同一菜单中保留当前仓的“助理授权”，沿用原有管理员校验。

授权区只显示当前仓的真实授权数量，不显示 Key 明文、前缀或 MCP 配置，也不生成、撤销或扩展现有 Key。界面不维护另一份数据仓。

## 数据和安全边界

- 沿用万象当前账号、设备和数据仓上下文；切换或会话失效会阻断旧响应并清理详情与对话框。
- 图谱继续使用实际服务端节点、关系和证据；没有可用图谱时显示真实空态或错误，不代入演示知识。
- 保留电脑及万象空间导入、既有分块上传和实际任务状态；不以定时器伪造处理百分比或生成实体。
- 来源展示明确区分当前正文与固定版本正文。历史正文必须返回匹配的 `version_id`；范围由后端按实际长度截断，可继续读取后续范围。
- 同仓来源与待确认详情使用独立请求序号，避免较慢的旧选择覆盖新选择。关闭详情、切仓和重新选择会使旧读取失效。
- 反馈、建议、确认应用和撤回反馈使用真实治理接口、实际 revision 和稳定 operation ID。尚未确认的操作不能被另一项写操作覆盖；未知结果只能复用原标识查询或重试。
- AI 建议必须属于发起的 review，显示修改前后及证据；只有服务端返回 `ready` 才提供单独确认应用。`insufficient` 保持待核对，不自动补全身份或结论。
- 模型建议运行期间锁定事项选择和提交对话框取消，避免将 A 的建议附到 B。切换账号或仓后旧结果不得附着到新上下文。
- 后台标记为暂停的知识在管理图谱中保留问题说明，使用虚线区分；对外暂停及恢复由服务端执行，界面不以本地状态代替结果。

服务适配仍使用明确白名单和既有账号权限，不向简化页面开放任意地址、任意后端请求或模型密钥。团队版仍仅管理员可以维护团队数据。
