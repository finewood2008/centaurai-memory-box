# 万象工坊（个人版）

工坊位于个人版一级入口「工坊 Beta」，项目列表名称为「本地应用」。万象应用分为「应用市场／我的应用」，取消手动导入私有应用包入口。选择已有应用后创建独立副本，直接进入开物的持续修改工作台；不经过新建产品、首次访谈或 PRD 确认。不改变企业版入口和管理员权限。

## 使用与数据

1. 在「我的应用」点击已校验的「用工坊修改」，自动带入来源；已有定制副本时直接定位现有项目。工坊不提供独立选择来源或新建项目入口；仅管理已经进入的本地应用。
2. 确认副本名（默认「原名 · 我的定制」），创建后直接修改。原应用、业务记录、资料授权和应用模型配置都不会复制。
3. 左侧发送文字，或在真实预览里标记最多六处位置，一轮提交。复用原修改队列、阶段状态、停止、重试和版本历史。
4. 先试用，再「采用并安装」。定制版由当前盒子保存为工坊「本地应用」，启用后作为独立应用出现在「我的应用」；另一台电脑需按需安装运行组件。安装确认失败后可以再次安装并补记回执。
   未发送的文字按账号、盒子和项目保存；工作台重开可恢复。恢复的标记保留文字，重新定位后再发送。
5. 恢复只恢复代码及兼容配置，不回滚业务数据。原版更新不自动合入副本。

主模型在工坊详情「应用主模型」配置；修改与需求理解直接调用 WANX 当前默认模型，不启动 Codex／ACP；每轮开始冻结模型选择，下一轮跟随新的默认配置，两者分开。默认模型不可用时保留修改草稿并报错，不退回 Codex。

模型只拥有受控的源码读取、唯一文本替换、已选背景读取及编译校验工具，不获得 Shell、任意文件或额外网络权限。支持图像的默认模型接收圈选截图；文本模型依据标记文字、坐标和源码定位，不能确定时询问，不假称看过截图。

## 可编辑包约定

不反编译应用，也不把安装后的 JavaScript bundle 当作原始源码。包内必须明确提供 `wanx.editable.json`：

```json
{
  "allowed": true,
  "format": "wanx-miniapp-source-v1",
  "applicationId": "ai.example.app",
  "version": "1.0.0",
  "origin": "local",
  "sourceHash": "完整 files 对象的 SHA-256",
  "files": {
    "miniapp.manifest.json": "清单的 JSON 字符串",
    "src/app.js": "export function mount(root, api) { /* ... */ }",
    "src/styles.css": "/* ... */"
  }
}
```

`sourceHash` 使用 UTF-8 JSON：键递归排序、无多余空格、不转义中文（Python `digest(files)`）。64 文件、单文件 512 KiB、合计 2 MiB；文件名和依赖遵守现有开物受控编译器限制。名称、版本、摘要与当前安装对象必须一致。用户不能从 renderer 指定读取本机任意路径。

首版兼容受控小应用的 `data / model / files`。需要企业私有报告、企业知识运行授权、独立后台、任意 Node/Python 依赖或不提供源码的应用标明暂不兼容，不假装能直接修改。可以在「资料与能力」重新选择本人空间与个人星图背景材料；背景资料不等于应用运行授权。

云端没有提供可编辑源码的应用明确显示不支持，不增加本地产品名单或源码兜底。支持的市场应用可以由发行方在现有应用包中加入上述文件。新工坊生成的安装包会保留可编辑声明与源码，便于再次定制。

## 实现与部署

- 私有服务 `/api/_client/workshop`，运行于盒端，与现有 `/api/app-studio` 公开接口独立；项目存放在当前 WANX home 的 `.wanx-workshop`，沿用用户 ID 隔离。
- `/sources` 只读本人开物源码；`POST /copies` 校验、重编译并原子创建副本，操作 ID 幂等；其他受限项目、迭代、预览、主模型和安装回执复用开物实现。首次访谈和从零构建路由被拒绝。
- 本地信任通道使用个人 `wanx` 资源；不借用 `team:management`，团队上下文拒绝访问工坊。任务复用已有租约、撤权监测和进程清理。
- 安装包固定 `runtimeNamespace: workshop`。安装后的应用只能访问本人相应运行会话，不能读取工坊列表、源码或修改其他应用。
- 个人客户端使用 `node apps/builder/tools/assemble-client.mjs personal` 生成运行文件，正常 `build:studio` / 打包前流程自动执行。生成物位于 `apps/personal-client/workshop`、`shell/personal-workshop.mjs` 等，已加入忽略规则；不要提交构建物与运行数据。
- 必须同时部署匹配的盒端组件、本地数据通道策略和个人客户端。旧盒端显示需要更新，不伪造成功。企业版不新增工坊 Tab。

## 验证

回归覆盖许可／格式／摘要／越界路径校验、原子重复创建、账号隔离、试用和正式数据隔离、原应用不变、直接迭代、版本恢复、客户端草稿重试、切换上下文丢弃迟到响应以及有限路由策略。真实模型调用、已安装客户端和目标盒子结果应分别记录，不能用合成修改器冒充真实 Codex 验收。
